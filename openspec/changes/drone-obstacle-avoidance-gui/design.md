## Context

当前无人机避障系统是一个基于 EasyX 的 C++ 单文件程序（`无人机避障系统.cpp`），使用 Windows Multimedia API 播放音效。游戏直接进入主循环，无菜单、无 HUD、无设置。操控仅支持键盘 W/A/S/D。需要在不引入新外部依赖的前提下，通过重构主文件实现完整的 GUI 交互。

## Goals / Non-Goals

**Goals:**
- 实现完整游戏状态机（菜单 → 游戏中 → 暂停 → 结束 → 菜单循环）
- 提供主菜单、设置面板、HUD、游戏结束四个 GUI 界面
- 支持鼠标点击按钮和区域交互
- 保持原有键盘操控兼容
- 所有 GUI 使用 EasyX 原生绘图（矩形、文字、图片），无需新依赖

**Non-Goals:**
- 不引入第三方 UI 框架（如 Qt、MFC）
- 不添加网络功能或排行榜
- 不改变原有避障碰撞逻辑
- 不重写音效播放机制

## Decisions

**1. 状态机架构：枚举 + switch 分发**
选择在 `main()` 中用 `enum GameState` + `switch` 分发到各状态的处理函数，而非类继承或多态。理由：当前代码是过程式风格，最小化重构范围；EasyX 程序通常不使用复杂 C++ 特性；状态数量固定（4 个），switch 可读性足够。

**2. GUI 按钮：矩形区域 + 鼠标碰撞检测**
用 `RECT` 结构体定义按钮位置，在消息循环中检测 `WM_LBUTTONDOWN` 坐标是否落在按钮区域内。理由：EasyX 没有原生按钮控件，自绘最直接；可以用 `fillroundrect` + `outtextxy` 绘制圆角按钮。

**3. 设置数据存储：全局结构体 `Settings`**
用一个全局 `Settings` 结构体存储音效开关、音量、难度等参数，在各模块间共享。理由：现有代码已大量使用全局变量，保持一致风格；单文件程序无需序列化/文件持久化。

**4. HUD 实现：每帧叠加绘制**
在 `show()` 中先绘制游戏画面，再叠加 HUD 文字和背景条。使用半透明矩形作为 HUD 背景，`settextstyle` + `outtextxy` 绘制信息文字。理由：不引入额外图层复杂度，与现有批次绘制（`BeginBatchDraw`/`FlushBatchDraw`）兼容。

**5. 屏幕方向按钮：固定右下角 D-Pad 布局**
在游戏画面上绘制上下左右四个三角形/箭头区域，点击触发对应方向移动。理由：直观的移动端风格操控，不占用键盘。

## Risks / Trade-offs

- [分文件风险] 当前为单文件，GUI 代码增加后文件可能过大（预计 800-1000 行） → 用 `#pragma region` 分区注释组织代码，若后续需要可拆分为多个 .cpp/.h
- [性能风险] HUD 每帧叠加绘制增加少量计算 → EasyX 的 `FlushBatchDraw` 已做双缓冲优化，额外绘制操作可忽略
- [兼容性风险] 使用 `GetMouseMsg()` 获取鼠标消息可能与 `kbhit()` 轮询冲突 → 统一使用 EasyX 的 `MOUSEMSG` 和 `ExMessage` 机制，替换 `kbhit()/getch()` 为事件驱动

## Open Questions

- 是否需要触屏支持？（当前设计已通过鼠标覆盖，触屏天然兼容）
- 难度选择是否影响障碍物生成参数？（低/中/高难度影响 UAV 移动速度）
